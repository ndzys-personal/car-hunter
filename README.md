# Car Hunter MVP

Car Hunter збирає оголошення BMW E90 Sedan/E91 Touring та E60 Sedan/E61 Touring з OTOMOTO, OLX і Allegro, нормалізує їх, зберігає історію в Supabase, рахує preference-aware deterministic score, оцінює кожне нове оголошення через Gemini й надсилає його в Telegram разом з AI-балом і вердиктом.

## Вимоги

- Node.js 22+
- pnpm 10+
- проєкт Supabase
- Telegram-бот
- Gemini API key
- шість широких пошукових URL (E91/E61 для трьох маркетплейсів)

## 1. Локальне встановлення

```bash
pnpm install
pnpm exec playwright install chromium
cp .env.example .env
```

Заповніть `.env`. Реальні секрети не комітьте. Межі ціни й року можна змінити в `src/config/searches.ts`; пошукові URL мають бути ширшими за остаточні критерії.

## 2. Supabase

Створіть проєкт, скопіюйте Project URL і service-role key у `.env`, потім застосуйте міграцію:

```bash
pnpm dlx supabase login
pnpm dlx supabase link --project-ref YOUR_PROJECT_REF
pnpm dlx supabase db push
```

Міграції створюють також VIN-рівень `vehicles`, зовнішні `historical_listings` і детерміновані `vehicle_history_signals`. Один валідний нормалізований VIN зв'язує багато оголошень із різних маркетплейсів; без VIN автомобілі не об'єднуються за моделлю, роком або кольором. RLS увімкнений без публічних політик: бекенд працює service-role ключем. Для власного dashboard додайте окремі read-only політики.

## 3. Telegram

1. Створіть бота через `@BotFather` і внесіть токен у `.env`.
2. Надішліть боту будь-яке повідомлення.
3. Отримайте chat ID:

```bash
pnpm telegram:chat-id
```

Скопіюйте ID у `TELEGRAM_CHAT_ID`.

Перевірте з’єднання тестовим повідомленням:

```bash
pnpm test:telegram
```

Старий alias `pnpm telegram:test` також підтримується.

## 4. Обов’язковий baseline

Перший запуск записує поточні оголошення як уже відомі й ніколи не надсилає Telegram-сповіщення:

```bash
pnpm baseline
```

Варіанти для дешевшої/точкової перевірки:

```bash
pnpm baseline -- --skip-ai
pnpm baseline -- --source=otomoto
pnpm baseline -- --profile=bmw-e91
```

Точкові варіанти з `--source` або `--profile` зберігають дані, але навмисно не виставляють глобальний прапорець завершення. Після діагностики все одно виконайте повний `pnpm baseline` без фільтрів.

Перевірте в Supabase, що `listings` та `listing_snapshots` заповнені, дублі не виникли, а `app_state.baseline_completed` має значення `true`.

Baseline запам’ятовує окремо кожну активну пару профіль/джерело разом із відбитком пошукового URL. Якщо пізніше змінити фільтри URL, додати новий URL або ввімкнути нове джерело, звичайний scan зупиниться без сповіщень, доки ви знову не виконаєте повний baseline. Це не дозволяє вже наявним оголошенням із розширеного пошуку масово потрапити в Telegram як нові.

## 5. Звичайне сканування

```bash
pnpm scan
```

Якщо baseline не завершений, команда безпечно відмовиться від моніторингу й не надішле жодного повідомлення. Кожне спостереження зберігається у `listing_snapshots`, але тільки оголошення без deterministic hard reject із балом не нижче `AI_SCORE_THRESHOLD` переходять до VIN/history та AI. Незмінне оголошення не аналізується повторно. Зміна опису, VIN, продавця або ціни створює нову матеріальну версію в БД, але не створює повторного Telegram-сповіщення.

Політика рекомендацій враховує особисті преференції: E90/E91 та E60/E61 повністю допустимі, Touring отримує лише `+5` за практичність, RWD — `+5`, xDrive — `-8` без hard reject. Неоднозначний двигун не вгадується з високою впевненістю, а `PILNE` можливе лише від 90 балів за високої впевненості й без суттєвих невідомих. Дані продавця зберігаються окремо як declared/inferred тип, confidence і конкретні signals.

### Listing History / VIN Intelligence

Для перспективного оголошення з валідним VIN система спочатку читає власні snapshots усіх маркетплейсів, а потім — якщо кеш прострочений — шукає точні публічні входження VIN. MVP використовує звичайний публічний web search і перевіряє сторінку-джерело; сам snippet не стає надійним історичним фактом. CAPTCHA, автентифікація, paywall та захист маркетплейсу не обходяться.

Перед Gemini детерміновано обчислюються історія ціни, мінімальний відомий період появи в оголошеннях, зміни пробігу, попередній стан `uszkodzony`/`nie odpala`, зміни продавця та лише ймовірний `possible_flip`. Кожен сигнал зберігає evidence URL. Сильні підтверджені сигнали знижують фінальний бал; довга присутність сама по собі дає лише малий контекстний штраф і не відхиляє авто. Telegram додає коротку польську секцію історії тільки тоді, коли вона реально впливає на рішення.

Зовнішній пошук кешується на `HISTORY_SEARCH_TTL_DAYS` (типово 7). `HISTORY_SEARCH_ENABLED=false` вимикає зовнішнього провайдера, не вимикаючи внутрішню VIN-історію. Нове marketplace-оголошення або зміна продавця для того самого VIN оновлює кеш раніше. Ручний запуск `pnpm analyze <listing-id> --refresh-history` примусово оновлює його.

### Свіжість оголошення

Для кожного запису зберігаються три незалежні часові значення:

- `published_at` — дата публікації, яку надійно надав маркетплейс; інакше `null`;
- `first_seen_at` — перше виявлення Car Hunter, встановлюється один раз;
- `last_seen_at` — останній успішний scan, у якому оголошення ще було активне.

`first_seen_at` не використовується як заміна дати публікації. Якщо маркетплейс покаже новішу дату після редагування, Car Hunter збереже найраніший надійний `published_at`. Новим для системи оголошення є лише нова пара `source + source_listing_id`; baseline ніколи не надсилає Telegram.

Freshness bonus налаштовується для кожного профілю в `src/config/searches.ts`: за замовчуванням до 24 годин — `+4`, до 72 годин — `+2`, старіша або невідома дата — `0`. Старі оголошення не штрафуються. Telegram окремо показує час публікації та першого виявлення.

### Тип продавця

Car Hunter не довіряє сліпо позначці `osoba prywatna`. Детермінований аналіз поєднує незалежні сигнали з тексту (VAT marża, фінансування, trade-in, komis, професійна мова), приватний контекст володіння та публічно доступні дані профілю продавця. AI інтерпретує повний набір доказів, але сирі `sellerSignals` завжди зберігаються.

Оцінка `sellerConfidence` означає ймовірність поведінки дилера: `0–20% private`, `21–40% likely_private`, `41–59% uncertain`, `60–79% likely_dealer`, `80–100% dealer`. Приватний/імовірно приватний продавець дає `+6`, імовірний дилер `-6`, дилер `-10`; це ніколи не є hard reject.

Якщо маркетплейс відкрито надає стабільний seller ID/URL, система накопичує лише мінімальну marketplace-історію: кількість унікальних оголошень авто, марок, перше й останнє спостереження. Зовнішній пошук особи та інвазивний збір персональних даних не виконуються. Без стабільного публічного ідентифікатора різних приватних продавців не об’єднують за самим ім’ям.

## 6. Ручна AI-перевірка

Скопіюйте UUID із колонки `listings.id` у Supabase і проаналізуйте одну машину:

```bash
pnpm analyze <listing-id>
```

Команда повторно рахує deterministic score, запускає Gemini, зберігає результат у
`listing_analysis` і друкує JSON у термінал. Telegram вона не викликає.

Для ручної перевірки повного ланцюжка AI → Telegram:

```bash
pnpm analyze <listing-id> --send
```

Тестове повідомлення надсилається напряму й не створює запис у бойовій таблиці
`notifications`.

## 7. GitHub Actions

Workflow `.github/workflows/scan.yml` запускається щогодини й вручну. До ввімкнення cron:

- додайте Secrets: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `GEMINI_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`;
- додайте Variables: шість `*_E91_URL`/`*_E61_URL` із `.env.example`;
- локально виконайте baseline;
- один раз запустіть workflow вручну та перевірте лог.

За потреби задайте Variables `GEMINI_MODEL`, `MAX_LISTINGS_PER_SOURCE`, `MAX_SEARCH_PAGES`, `DETAIL_CONCURRENCY`, `AI_SCORE_THRESHOLD`, `HISTORY_SEARCH_ENABLED`, `HISTORY_SEARCH_TTL_DAYS`. `AI_SCORE_THRESHOLD` є спільним cost-control gate для VIN web search та AI. Адаптери проходять сторінки пагінації до цих захисних лімітів і обробляють до трьох detail-сторінок паралельно; для повного першого імпорту ліміти мають покривати весь обсяг результатів кожного пошуку.

## Важливі обмеження MVP

- Адаптери використовують браузер і віддають перевагу JSON-LD/семантичним даним сторінки, без обходу CAPTCHA чи інших механізмів захисту. Перед використанням перевірте актуальні правила кожного маркетплейсу та задайте помірну частоту запуску.
- AI оцінює лише якість оголошення, відповідність профілю й поведінку продавця; це не технічна діагностика автомобіля.
- Значення за замовчуванням — актуальна стабільна бюджетна модель `gemini-3.5-flash-lite`; модель конфігурується через `GEMINI_MODEL`.
